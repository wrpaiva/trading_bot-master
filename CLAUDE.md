# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Demo arbitrage bot that monitors WETH/SHIB price on Uniswap V2 and Sushiswap, and executes a DyDx flash-loan-funded arbitrage trade when the price spread exceeds a threshold. It runs against a **mainnet fork** (Ganache forking Ethereum via Alchemy), not real funds. Node.js + web3 off-chain bot driving a Solidity contract.

## Commands

Node 16.14.2 is recommended (per README) to avoid dependency issues. `truffle` and `ganache` are expected as global installs.

```bash
npm install                     # install deps
truffle migrate --reset         # compile + deploy Arbitrage.sol to local Ganache (writes build/contracts/)
node ./bot.js                   # start the bot (monitors Swap events, also boots the express server)
node ./scripts/manipulatePrice.js   # force a price swing on Uniswap to trigger an arbitrage opportunity
```

Start Ganache first (separate terminal), forking mainnet and unlocking a token-holding account:

```bash
ganache -f wss://eth-mainnet.alchemyapi.io/v2/<KEY> -m <mnemonic> -u 0xdEAD000000000000000042069420694206942069 -p 7545
```

The `-u` account must hold the `ARB_AGAINST` token (default SHIB); change it if switching tokens.

**Tests:** none exist. The `test/` dir is empty and `npm test` is a no-op stub — don't trust it as a signal.

## Configuration split

Two config sources, and knowing which lives where matters:

- **`.env`** (copy from `.env.example`) — runtime/strategy values: `ARB_FOR`/`ARB_AGAINST` (token addresses), `ACCOUNT` (receives profit), `PRICE_DIFFERENCE` (spread % threshold), `GAS_LIMIT`/`GAS_PRICE`, `UNITS` (display precision), `ALCHEMY_API_KEY`.
- **`config.json`** — exchange router/factory addresses plus two toggles under `PROJECT_SETTINGS`:
  - `isLocal` — `true` connects web3 to `ws://127.0.0.1:7545`; `false` connects to mainnet via Alchemy WSS.
  - `isDeployed` — when `false`, `executeTrade()` skips the on-chain contract call (monitor-only mode; no deployed contract needed).

## Architecture / control flow

`bot.js` is the orchestrator with five functions forming a pipeline, re-entrancy-guarded by the `isExecuting` flag:

1. `main()` — subscribes to `Swap` events on both the Uniswap and Sushiswap pair contracts.
2. `checkPrice()` — reads reserves, computes the % price difference between exchanges.
3. `determineDirection()` — returns `[buyRouter, sellRouter]` if spread ≥ `PRICE_DIFFERENCE`, else `null`.
4. `determineProfitability()` — the **strategy logic you customize** (~line 137). Uses `getAmountsIn`/`getAmountsOut` against reserves of the lower-liquidity pool to size the trade and estimate profit; returns bool and sets the module-level `amount`.
5. `executeTrade()` — calls `arbitrage.executeTrade(...)` on-chain (only if `isDeployed`).

Supporting modules:

- `helpers/initialization.js` — builds the shared web3 instance and the Uniswap/Sushiswap factory + router contract objects, and the `arbitrage` contract. **Both this file and `helpers/helpers.js` independently create their own web3 connection** based on `config.isLocal`.
- `helpers/helpers.js` — pure blockchain reads: token metadata, pair address lookup, reserves, price (`Big.js`), estimated return.
- `helpers/server.js` — required for side effect only; spins up an Express server on `PORT`/5000. Serves no real purpose beyond keeping the process alive / legacy scaffolding.

Contract (`contracts/Arbitrage.sol`, Solidity 0.8.9):

- `Arbitrage extends DyDxFlashLoan`. `executeTrade()` initiates a DyDx flash loan; DyDx calls back into `callFunction()` which does the two swaps (buy on one router, sell on the other via `swapExactTokensForTokens`) and transfers profit to `owner`. `require(balanceAfter - balanceBefore == flashAmount ...)` enforces the loan arrived; the whole tx reverts if the round-trip isn't profitable enough to repay `flashAmount + 1`.
- Constructor takes `(sRouter, uRouter)` — Sushiswap first. Migration `2_deploy_contracts.js` passes them in that order from `config.json`.

## Gotchas

- **`initialization.js` hardcodes `IArbitrage.networks[1].address`** — it reads the deployed address for network id `1`. After `truffle migrate` against Ganache, the address is keyed by Ganache's network id; the bot expects the build artifact to expose it under `1`. If the bot can't find the contract, this line is why.
- `build/contracts/Arbitrage.json` is generated by `truffle migrate` and required at runtime — the bot won't start without migrating first.
- Strategy assumes the buy-side (Uniswap in the demo) has higher reserves than the sell-side. Reversed direction can revert; `determineProfitability()` wraps the estimate in try/catch and resumes monitoring on error (see README "Strategy Overview").
- After running `manipulatePrice.js`, restart Ganache and re-migrate to reset fork state before retesting.

## Switching tokens / chains

Change `ARB_FOR`/`ARB_AGAINST` in `.env`, the Ganache `-u` unlocked account, and `UNLOCKED_ACCOUNT`/`AMOUNT` in `manipulatePrice.js`. For a different EVM chain also update router/factory addresses in `config.json`, the web3 RPC URLs in `initialization.js` and `helpers.js`, and the flash-loan provider in `Arbitrage.sol` (DyDx is Ethereum-only).
